## Tables and key constraints

### books

Columns:
- `id` PK (uuid text)
- `name`
- `is_active` (indexed)
- `default_payables_account_guid` FK -> `accounts.id` (nullable, indexed)
- `default_receivables_account_guid` FK -> `accounts.id` (nullable, indexed)
- `default_iss_recoverable_account_guid` FK -> `accounts.id` (nullable, indexed)
- `created_at`

Notes:
- unique partial index enforces single active book where supported.

### document_number_counters

Columns:
- `book_id` FK -> `books.id` (cascade delete)
- `owner_type`
- `next_value`
- `width`

Constraints:
- composite PK (`book_id`, `owner_type`)
- `next_value >= 1`
- `width >= 1`

### users

Columns:
- `id` PK (uuid text)
- `email` (unique, normalized by service layer)
- `password_hash`
- `full_name`
- `is_active`
- `is_superuser`
- `created_at`, `updated_at`

Indexes:
- unique `email`

### user_book_access

Columns:
- `user_id` FK -> `users.id` (cascade delete)
- `book_id` FK -> `books.id` (cascade delete)
- `role` (`VIEWER` | `EDITOR`)
- `created_at`

Constraints:
- composite PK (`user_id`, `book_id`)
- `role` check constraint (`VIEWER`, `EDITOR`)

Indexes:
- `book_id`

### commodities

Columns:
- `id` PK
- `namespace`, `mnemonic`, `fullname`, `fraction`, `quote`

Constraints:
- unique `(namespace, mnemonic)`.

### accounts

Columns:
- `id` PK
- `book_id` FK -> `books.id`
- `parent_id` FK -> `accounts.id`
- `name`, `code`, `description`, `type`, `commodity_id`, `is_placeholder`
- `created_at`, `updated_at`

Indexes:
- by `book_id`, `parent_id`, `name`, `commodity_id`
- composite `(book_id, parent_id, name)`

### customers / vendors

Columns (both):
- `guid` PK
- `book_id` FK -> `books.id`
- identity/contact fields
- `currency_guid` FK -> `commodities.id`
- customer: `income_account_guid` FK -> `accounts.id` (nullable, set-null)
- vendor: `expense_account_guid` FK -> `accounts.id` (nullable, set-null)
- `created_at`, `updated_at`

Checks:
- customer rational denominator checks (`discount_denom > 0`, `credit_denom > 0`).

### invoices

Columns:
- `guid` PK
- `book_id` FK -> `books.id`
- `currency_guid` FK -> `commodities.id`
- `owner_type`, `owner_guid` (polymorphic owner)
- header/posting fields (`id`, `invoice_type`, `date_opened`, `date_posted`, `post_txn`, `post_lot`, `post_acc`, ...)
- `created_at`, `updated_at`

Indexes:
- `book_id`, `currency_guid`, `owner_guid`, `(book_id, date_opened)`

Important note:
- FK on `owner_guid` was intentionally removed to support `CUSTOMER` and `VENDOR` ownership in the same column.
- Referential integrity is enforced in service-layer business validation.

### entries

Columns:
- `guid` PK
- `invoice` FK -> `invoices.guid` (cascade delete)
- `i_acct` FK -> `accounts.id`
- date/description/action/notes
- quantity, price, discount rationals
- discount/tax metadata
- `created_at`, `updated_at`

Checks:
- `quantity_denom > 0`
- `i_price_denom > 0`
- `i_discount_denom > 0`
- `i_tax_denom > 0`

### lots

Columns:
- `guid` PK
- `account_guid` FK -> `accounts.id`
- `is_closed`

### transactions

Columns:
- `guid` PK
- `currency_guid` FK -> `commodities.id`
- `num`, `post_date`, `enter_date`, `description`

Index:
- `post_date`

### splits

Columns:
- `guid` PK
- `tx_guid` FK -> `transactions.guid` (cascade delete)
- `account_guid` FK -> `accounts.id`
- `memo`, `action`, `reconcile_state`, `reconcile_date`
- `value_num/value_denom`, `quantity_num/quantity_denom`
- `lot_guid` (nullable)

Checks:
- `value_denom > 0`
- `quantity_denom > 0`

## Relational hardening policy

The implemented schema enforces deterministic constraints in the database where practical.
Business-specific cross-table rules (for example polymorphic owner and posting lifecycle restrictions) are enforced in application services and route validators.

## Legacy compatibility note

The original GnuCash physical schema remains a reference for historical data interpretation, but conformance in this repository is defined by this runtime profile plus API/domain specs.
